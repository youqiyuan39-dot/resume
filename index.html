Agent 工具调用

模型到底在哪里做决定？

运营在工作台关联一件商品后问助手：“这件商品为什么不能发布？”下面是这一问在代码里的完整路径。黄色步骤由模型决定，蓝色步骤由代码强制约束。

  • 模型决定选哪个工具、怎么解释、提出什么修改
  • 代码约束绑定商品、预取证据、校验回答、限制写入

上限：ReAct 最多 7 轮，工具调用最多 8 次；查询失败返回“本次未取得，不可推测”。

源码：src/workbench_assistant_worker.py（AgentScope ReAct）

运营这件商品为什么不能发布？

  1. 代码
    绑定当前商品

    本轮只回答已关联的这一件；工具参数里的商品名被强制为当前商品，换成别的商品直接报错。

    context.product = "节日门帘-draft.json"
  2. 代码
    预取证据

    推理前先查商品状态和最近处理日志，作为模型的上下文。

    inspect_product · get_product_logs
  3. 模型
    选择下一步查询

    首轮必须先调用读取工具，具体调哪个由模型决定：它要看完整缺项。

    inspect_product(detail_level="full")
  4. 模型
    根据工具结果解释缺项

    “缺包装重量和三边尺寸，条码豁免依据未取得，所以还不能发布。”

  5. 代码
    校验回答

    回答漏掉条码、重量、尺寸等关键缺项，或把内部工具名写进回答时，程序改为直接列出核对记录。

    checked_product_answer()
  6. 模型
    提出修改预览

    运营补充实测重量后，模型调用写工具准备修改。

    prepare_product_change({"packed_weight_g": 420})
  7. 代码
    校验执行条件

    写工具只生成待确认预览：字段限白名单，每轮只能有一个预览；运营确认后才写入，发布走独立的发布中心。

流程设计

把上架做成一台不会乱发的状态机

上架最怕两件事：模型判错还照样发出去，网络超时后重复刊登。悠悠把流程拆成证据、处理、校验、冻结、发布、回查六个串行阶段，任何一步不确定就停下隔离。

源码：src/autonomous_flow_v3.py
  1. 先落盘，再发布调平台接口前，先把任务写成 dispatching 并原子保存；进程中断后从原阶段续跑。
  2. 结果未知，只回查不重发发布时出任何异常都记为 unknown，转去回读平台，从设计上避免重复刊登。
  3. 以平台回执为完成标准拿到真实 item_id 且确认在线才算完成，否则隔离并写明原因，交给人处理。

    类目守卫

    链锯被判成锯片配件之后

    模型把手持链锯归成了锯片配件。V6 修正为手锯并补上型号规则，后来把“类目与商品类型冲突”的检查做成独立的类目守卫模块。悬停或点击截图上的数字看说明。

    1. 必填检查必填属性 7/7 齐全才放行，缺一项就停在待补信息。
    2. 类目路径纠正后：工具 > 手工具 > 锯。
    3. 型号规则型号只用有来源的厂家信息，不能把规格数字当型号。
    源码：src/category_guard_v3.py

    利润门

    差一点也不放行

    运行演示里的园艺修枝剪按市场价 ¥83 算出利润率 9.6%，被隔离。拖动售价看它什么时候能放行。规则：贡献利润 ÷ 买家售价，严格大于 10%，不自动抬价。

    专业 技能

    每一项都在悠悠里真实用过，上面的项目区能看到对应的东西。

    Agent 工作流设计

    能把一个业务流程拆成可恢复的阶段和状态，失败时知道停在哪、从哪续跑。

    对应实现六阶段发布状态机

    Python · 状态机 · 原子写入 JSON

    工具调用与 Prompt

    设计工具描述、参数约束和系统提示词，让模型在限定工具里选下一步。

    对应实现工作台助手、核查 Agent

    AgentScope ReAct · Function Calling · JSON 结构化输出

    规则校验

    把运营经验写成可执行的检查，模型说了不算，规则说了算。

    对应实现类目守卫、利润门禁

    型号规则 · 必填检查 · 回归验收用例

    知识检索（RAG）

    项目规则按来源和有效期过滤，关键词与中文向量混合检索后再给模型。

    对应实现项目知识库

    BM25 · BGE 中文向量 · RRF 融合 · 本地 Qwen

    数据采集与清洗

    从浏览器采集货源与平台数据，按 SKU 绑定原件、图片和包装信息。

    对应实现Chrome 采集扩展、本地接收端

    JavaScript · requests · pandas · 正则

    审核工作台

    给运营用的界面：缺什么、为什么停、下一步做什么，一眼看清。

    对应实现两套 Web 审核工作台

    HTML / CSS / JavaScript · RESTful API

    面试时可以现场讲的三件事

    2. 利润按买家售价怎么算，成本未知为什么不能当零
    3. 哪些交给模型、哪些必须由代码兜底
